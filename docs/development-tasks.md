# 开发任务清单

本文档用于后续逐项开发和评审。每个任务应尽量对应一个独立提交；任务完成时将复选框改为 `[x]`，并在任务下补充实际实现说明或偏差。

## 任务执行约定

- 开始任务前阅读产品、架构和数据/API 文档中对应章节。
- 一次只实现一个任务，除非任务之间无法独立验证。
- 不顺带重构无关代码。
- 数据库、后端接口和前端交互分开提交。
- 每个任务都应有明确验收结果。
- 权重、唯一约束、状态变更优先增加自动化测试。

## A. 项目基础

- [x] **A01 创建 Laravel 项目**
  - 初始化 Laravel 和环境变量模板。
  - 增加 `/api/health`。
  - 验收：接口能返回应用和数据库状态。
  - 实现：Laravel 13 项目已初始化；健康检查成功时返回 200，数据库不可用时返回 503。

- [ ] **A02 创建 Vue 项目**
  - 初始化 Vue 3、Vite、TypeScript、Router、Pinia。
  - 建立 `/`、`/gallery`、`/draw`、`/admin/review` 空路由。
  - 验收：四个路由可以独立访问。

- [ ] **A03 配置本地 API 代理**
  - Vite 将 `/api` 转发到 Laravel。
  - 建立统一 Axios 实例。
  - 验收：Vue 可以调用 `/api/health`。

- [ ] **A04 建立基础视觉主题**
  - 定义颜色、字体、圆角和间距变量。
  - 建立移动端、抽奖端、审核端基础布局。
  - 验收：各页面具有一致视觉风格。

## B. 用户身份

- [ ] **B01 建立 users 表**
  - 创建 Migration 和 Model。
  - 增加手机号、邀请码唯一索引。
  - 验收：Migration 可执行和回滚。

- [ ] **B02 实现手机号登记接口**
  - 新手机号创建用户，已有手机号恢复身份。
  - 生成访问令牌并只保存哈希。
  - 验收：相同手机号不会创建重复用户。

- [ ] **B03 实现用户 Token 中间件**
  - 解析 Bearer Token。
  - 提供 `/api/me`。
  - 验收：无效 Token 返回 401，有效 Token 返回用户。

- [ ] **B04 实现前端手机号登记**
  - 首次进入显示手机号弹窗。
  - Token 写入 `localStorage`。
  - 启动时调用 `/api/me` 恢复身份。
  - 验收：刷新页面不需要重新输入手机号。

## C. 照片数据与 OSS

- [ ] **C01 建立 photos 表**
  - 创建 Migration 和 Model。
  - 增加文件哈希和 Object Key 唯一索引。
  - 定义上传与审核状态。
  - 验收：可以创建 `preparing` 照片记录。

- [ ] **C02 增加 OSS 配置**
  - 增加 Bucket、Region、角色等环境变量。
  - 建立 Laravel OSS 配置文件。
  - 验收：缺少配置时返回明确错误。

- [ ] **C03 实现 OSS 临时凭证服务**
  - 限制上传目录和有效期。
  - 验收：浏览器可使用凭证上传测试文件。

- [ ] **C04 实现客户端 SHA-256**
  - 选择图片后计算哈希并显示计算状态。
  - 验收：同一文件计算结果稳定一致。

- [ ] **C05 实现上传准备接口**
  - 接收哈希、文件名、大小和 MIME。
  - 检查重复并创建或恢复 `preparing` 记录。
  - 返回照片 ID、Object Key 和临时凭证。
  - 验收：重复文件得到明确提示且不创建新记录。

- [ ] **C06 实现浏览器直传 OSS**
  - 调用准备接口并上传原图。
  - 展示上传进度和错误。
  - 验收：原图实际存在于 OSS。

- [ ] **C07 实现上传完成接口**
  - 校验照片归属并确认 OSS 对象存在。
  - 标记 `uploaded + pending`。
  - 验收：不存在的 OSS 对象不能完成登记。

- [ ] **C08 实现“我的照片”接口**
  - 返回当前用户照片及状态。
  - 验收：用户不能读取其他人的未审核照片。

- [ ] **C09 实现用户端上传列表**
  - 显示缩略图、上传状态和审核状态。
  - 失败项支持重试。
  - 验收：上传完成后立即显示照片。

- [ ] **C10 封装 OSS 图片 URL**
  - 提供 `thumbnail`、`gallery`、`review`、`draw` 预设。
  - 验收：页面组件不直接拼接 OSS 处理参数。

## D. 上传统计

- [ ] **D01 实现用户照片统计接口**
  - 统计上传成功、待审核、通过和拒绝数量。
  - 不计算或返回抽奖次数。
  - 验收：统计值与照片记录一致。

- [ ] **D02 实现上传页统计卡片**
  - 显示成功上传数量，可附带审核状态数量。
  - 验收：上传或审核变化后可以刷新统计。

## E. 审核后台

- [ ] **E01 实现简单管理员登录**
  - 密码读取环境变量。
  - 返回短期管理员 Token。
  - 验收：未登录不能访问审核接口。

- [ ] **E02 实现获取下一张待审核照片**
  - 返回最早待审核照片和剩余数量。
  - 验收：无照片时返回明确空状态。

- [ ] **E03 实现单张审核接口**
  - 支持 `normal`、`good`、`rejected`。
  - 写入审核时间。
  - 验收：审核完成后不再进入待审核队列。

- [ ] **E04 建立审核日志表**
  - 保存照片、原状态和新状态。
  - 验收：每次审核都有日志。

- [ ] **E05 实现撤销最近审核**
  - 恢复上一个状态。
  - 验收：撤销后照片进入正确队列。

- [ ] **E06 实现审核页面**
  - 显示大图、三个按钮和剩余数量。
  - 审核后自动加载下一张。
  - 验收：可用鼠标连续审核。

- [ ] **E07 增加审核快捷键**
  - `1` 普通、`2` 好、`3` 不要、`U` 撤销。
  - 防止重复提交。
  - 验收：可不使用鼠标连续审核。

## F. 照片墙

- [ ] **F01 实现照片墙接口**
  - 只返回 `normal` 和 `good`。
  - 支持分页。
  - 验收：待审核和拒绝照片不可见。

- [ ] **F02 实现移动端照片墙**
  - 使用双列网格或瀑布流。
  - 支持大图预览和继续加载。
  - 验收：目标数据量下浏览流畅。

- [ ] **F03 实现移动端双页导航**
  - 上传和照片墙之间切换。
  - 保持身份和必要的页面状态。
  - 验收：切换页面不重复登录。

## G. 点赞

- [ ] **G01 建立 photo_likes 表**
  - 增加 `(photo_id, user_id)` 唯一索引。
  - 验收：数据库层阻止重复点赞。

- [ ] **G02 实现点赞接口**
  - 仅允许点赞审核通过的照片。
  - 拒绝给自己的照片点赞。
  - 重复调用保持幂等。
  - 验收：同一用户同一照片最多一条点赞。

- [ ] **G03 实现取消点赞接口**
  - 只删除当前用户点赞。
  - 重复调用保持幂等。
  - 验收：多次取消不会产生业务错误。

- [ ] **G04 扩展照片墙点赞数据**
  - 返回有效点赞数、当前点赞状态和 `can_like`。
  - 验收：自己的照片 `can_like=false`。

- [ ] **G05 实现前端点赞交互**
  - 乐观更新，失败时回滚。
  - 自己的照片禁用点赞。
  - 验收：快速点击不会产生重复记录或错误数量。

## H. 邀请

- [ ] **H01 建立 invitations 表**
  - 定义邀请状态。
  - 被邀请人唯一。
  - 验收：一个用户只能绑定一个邀请人。

- [ ] **H02 增加邀请配置**
  - 增加展示开关、奖励开关和奖励权重。
  - 提供前端所需的只读配置。
  - 验收：关闭奖励不删除或修改历史邀请记录。

- [ ] **H03 保存邀请参数**
  - 读取 URL 邀请码并在登记前保存本地。
  - 登录时传给后端。
  - 验收：扫码后再登记仍能绑定邀请人。

- [ ] **H04 实现邀请关系创建**
  - 校验邀请码，禁止邀请自己，禁止覆盖已有邀请人。
  - 初始状态为 `registered`。
  - 验收：反复打开其他邀请链接不会改变关系。

- [ ] **H05 上传完成时更新邀请状态**
  - 首次上传成功改为 `uploaded`。
  - 保持幂等。
  - 验收：上传多张不会产生多条奖励关系。

- [ ] **H06 审核通过时确认邀请成功**
  - 第一张有效照片使邀请变为 `qualified`。
  - 保存生效照片和时间。
  - 验收：后续照片审核不会重复触发。

- [ ] **H07 实现邀请信息接口**
  - 返回邀请码、链接、状态统计和开关。
  - 验收：关闭奖励后仍能查看历史邀请状态。

- [ ] **H08 实现邀请二维码组件**
  - 根据链接生成二维码。
  - 支持保存图片或系统分享。
  - 只显示成功邀请人数，不显示抽奖次数。
  - 验收：扫码进入带有正确邀请码。

## I. 权重计算

- [ ] **I01 建立照片权重值对象**
  - 使用整数权重：普通为 `100 + 有效点赞数`，好为其两倍。
  - 应用点赞上限。
  - 验收：单元测试覆盖 0、上限内和超过上限的点赞数。

- [ ] **I02 实现有效点赞统计**
  - 排除上传者本人。
  - 利用唯一约束保证同一用户只计一次。
  - 验收：手工插入的本人点赞也不计入。

- [ ] **I03 实现用户照片权重汇总**
  - 汇总全部审核通过照片。
  - 验收：结果与逐张权重相加一致。

- [ ] **I04 实现邀请奖励权重**
  - 只统计 `qualified`。
  - 开关关闭或邀请人无有效照片时返回 0。
  - 验收：切换开关不修改历史邀请状态。

- [ ] **I05 实现用户总权重服务**
  - 汇总照片和邀请权重并输出明细。
  - 验收：测试覆盖普通、好、点赞和邀请组合。

## J. 抽奖数据

- [ ] **J01 建立 draw_rounds 表**
  - 保存状态、候选快照和设置快照。
  - 验收：可创建空轮次并序列化 JSON。

- [ ] **J02 建立 draw_winners 表**
  - 同一轮用户和中奖位置分别唯一。
  - 验收：数据库层阻止同轮重复用户。

- [ ] **J03 实现候选快照生成**
  - 查询有效用户与照片。
  - 计算照片、点赞和邀请权重。
  - 按配置排除历史中奖者。
  - 验收：快照生成后新增点赞不会改变快照。

- [ ] **J04 实现创建抽奖轮次接口**
  - 抽取人数读取服务端配置。
  - 校验候选人数。
  - 验收：候选不足时返回明确错误。

- [ ] **J05 实现加权随机工具**
  - 使用累计权重算法。
  - 支持连续抽取不同用户。
  - 测试时可注入确定性随机源。
  - 验收：零权重不会被抽中。

- [ ] **J06 实现中奖展示照片选择**
  - 在中奖用户快照照片中按照片权重抽取。
  - 验收：不会选择快照以外或无效照片。

- [ ] **J07 实现提交中奖结果接口**
  - 验证用户、照片、位置均属于当前快照。
  - 保存结果并完成轮次。
  - 验收：不能提交快照外结果。

- [ ] **J08 实现历史中奖接口**
  - 返回轮次、照片和手机号尾号。
  - 验收：页面刷新后历史结果仍存在。

## K. PC 抽奖页

- [ ] **K01 建立抽奖页面布局**
  - 适配 1920×1080。
  - 包含标题、照片背景、按钮和中奖区域。
  - 验收：全屏无滚动条。

- [ ] **K02 加载和预取候选图片**
  - 展示缩略图并预加载抽奖大图。
  - 失败图片使用占位图。
  - 验收：已加载图片在临时断网时仍可展示。

- [ ] **K03 实现候选快照准备流程**
  - 点击准备后创建轮次并显示候选统计。
  - 防止重复创建。
  - 验收：本轮数据被冻结。

- [ ] **K04 实现前端加权抽取**
  - 使用候选快照抽取配置数量的不同用户。
  - 为每位用户选择展示照片。
  - 验收：结果满足权重和去重规则。

- [ ] **K05 实现照片云动画**
  - 图片随机移动、缩放和切换。
  - 低性能设备降低同时显示数量。
  - 验收：动画卡顿不改变预先确定的结果。

- [ ] **K06 实现中奖揭晓**
  - 逐个展示中奖照片和手机号尾号。
  - 验收：不暴露完整手机号。

- [ ] **K07 保存和恢复中奖结果**
  - 提交失败时本地暂存并支持重试。
  - 页面刷新后恢复历史结果。
  - 验收：刷新或短暂断网不丢结果。

## L. 现场可靠性

- [ ] **L01 增加上传文件校验**
  - 限制 MIME、扩展名和大小。
  - 验收：非法文件在前后端均被拒绝。

- [ ] **L02 增加上传失败重试**
  - 复用已有照片记录，不产生重复数据。
  - 验收：上传中断后可以继续或重新上传。

- [ ] **L03 增加抽奖图片预加载状态**
  - 显示加载进度和失败数量。
  - 达到最低加载比例后才允许开始。
  - 验收：现场操作人员能明确判断是否就绪。

- [ ] **L04 增加候选快照导出**
  - 可将当前快照下载为 JSON。
  - 验收：导出文件可用于现场备份核对。

- [ ] **L05 增加后台统计面板**
  - 展示用户、上传、审核、点赞和邀请数量。
  - 验收：统计与数据库一致。

- [ ] **L06 增加 200 用户模拟数据**
  - 生成模拟用户、照片、点赞和邀请。
  - 验收：核心查询和页面在目标数据量下正常。

- [ ] **L07 完整现场彩排**
  - 执行扫码、登记、上传、审核、点赞、冻结、抽奖和刷新恢复。
  - 验收：记录所有问题并在婚礼前关闭阻断项。

## 推荐实施顺序

核心闭环：

```text
A → B → C → D → E → F → G → I → J → K
```

邀请功能可以在核心上传与审核稳定后并行插入：

```text
H01-H08 → I04-I05 → J03
```

最后完成现场可靠性任务：

```text
L01-L07
```
