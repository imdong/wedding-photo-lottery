# 产品需求与业务规则

## 1. 项目目标

在婚礼当天提供一个面向亲友的照片互动系统：宾客扫码后上传婚礼照片、浏览照片墙并点赞；工作人员审核照片；仪式结束后在 PC 大屏进行加权抽奖。

系统最多约 200 名用户，仅使用一天，不需要短信验证、复杂权限或高并发架构，但必须保证照片上传、审核、点赞约束和抽奖结果稳定可靠。

## 2. 用户端

移动端是一个 Vue SPA，包含两个可以相互切换的页面：

- 上传页
- 照片墙

### 2.1 身份登记

- 用户首次打开页面时输入手机号。
- 不发送短信验证码。
- 手机号在系统中唯一。
- 后端返回随机访问令牌，保存在浏览器 `localStorage`。
- 再次打开时自动恢复身份。
- 更换浏览器或清理缓存后，可重新输入同一手机号恢复身份。

### 2.2 照片上传

- 用户选择手机中的图片原图。
- 浏览器分别记录压缩前原始文件和实际上传文件的 SHA-256；当前未压缩时两个值相同。
- 原图由浏览器直接上传到 OSS，不经过 Laravel 服务器。
- Laravel 负责签发临时上传凭证、预占照片记录、确认上传结果和保存业务数据。
- 任一哈希命中已有记录时自动跳过，不重复上传。
- 同一张照片经过不同截图、裁剪或压缩后仍可能产生不同哈希，不要求自动识别这种内容级重复；可由审核人员处理。
- 单张文件大小和允许的图片类型由配置控制。
- 上传失败应支持重试，重试不能产生重复照片记录。

### 2.3 用户端统计

上传页显示：

- 上传成功照片总数
- 待审核照片数
- 审核通过照片数

不展示“抽奖次数”或计算后的抽奖权重。

“上传成功”表示原图已经上传到 OSS，并由后端确认登记成功，无论是否已经审核。

## 3. 照片审核

每张照片具有以下审核状态：

| 状态 | 含义 | 进入照片墙 | 进入抽奖 |
|---|---|---:|---:|
| `pending` | 待审核 | 否 | 否 |
| `normal` | 普通 | 是 | 是 |
| `good` | 好 | 是 | 是 |
| `rejected` | 不要 | 否 | 否 |

审核后台应支持：

- 逐张显示待审核照片
- “普通”“好”“不要”三个大按钮
- 键盘快捷键连续审核
- 显示剩余待审核数量
- 撤销最近一次审核

## 4. 照片墙与点赞

- 照片墙只展示 `normal` 和 `good` 的照片。
- 使用 OSS 图片处理参数展示缩略图或预览图，不额外保存缩略图文件。
- 每个用户对同一张照片最多点赞一次。
- 用户可以取消自己的点赞。
- 前端禁止用户给自己上传的照片点赞。
- 后端也拒绝自己的点赞；即使数据库中意外出现本人点赞，权重计算时也必须排除。
- 点赞数在照片墙中显示。

## 5. 抽奖权重

### 5.1 单张照片权重

有效点赞数不包含照片上传者自己的点赞，且同一用户最多计一次。可配置点赞计数上限，建议默认最多计算 100 个有效点赞。

```text
点赞基数 = 1 + min(有效点赞数, 点赞上限) × 0.01
普通照片权重 = 点赞基数
好照片权重 = 点赞基数 × 2
待审核或不要 = 0
```

示例：

| 审核结果 | 有效点赞 | 最终权重 |
|---|---:|---:|
| 普通 | 0 | 1.00 |
| 普通 | 20 | 1.20 |
| 好 | 0 | 2.00 |
| 好 | 20 | 2.40 |

审核评价是主要因素，点赞只产生轻微加成。

### 5.2 用户权重

抽奖采用“先抽用户，再选展示照片”的两层方式：

```text
用户照片权重 = 用户全部审核通过照片的权重之和
用户邀请权重 = 成功邀请数 × 单次邀请奖励权重
用户总权重 = 用户照片权重 + 用户邀请权重
```

用户中奖后，再从其审核通过照片中按各照片自身权重随机选出一张，在大屏展示。

默认规则：

- 同一轮内同一个手机号最多中奖一次。
- 是否排除历史轮次中奖者作为配置项，婚礼当天建议开启。
- 最终只展示手机号尾号，不展示完整手机号。

## 6. 邀请功能

每个用户拥有唯一邀请码和邀请链接，移动端根据邀请链接生成二维码。

邀请状态：

| 状态 | 含义 |
|---|---|
| `registered` | 被邀请人通过链接完成手机号登记 |
| `uploaded` | 被邀请人成功上传至少一张照片 |
| `qualified` | 被邀请人至少一张照片审核通过，奖励生效 |
| `invalid` | 邀请无效 |

规则：

- 不能邀请自己。
- 每个被邀请人只能绑定一个邀请人。
- 已绑定后不能通过其他邀请链接更换邀请人。
- 同一个被邀请人最多贡献一次奖励。
- 邀请人必须至少有一张审核通过照片，邀请奖励才可进入抽奖。

邀请展示和抽奖奖励分别配置：

```env
INVITATION_ENABLED=true
INVITATION_REWARD_ENABLED=true
INVITATION_REWARD_WEIGHT=1
```

关闭奖励时保留邀请关系和状态记录，但计算抽奖候选池时不增加权重。

## 7. PC 抽奖页

PC 抽奖页无需登录，适配 1920×1080 全屏显示，包含：

- 审核通过的照片缩略图背景墙
- 准备抽奖和开始抽奖按钮
- 照片云随机运动动画
- 中奖照片大图
- 上传者手机号尾号
- 本轮及历史中奖结果

每轮抽取数量由后端配置或代码常量指定，不需要现场自由输入。

点击“准备抽奖”时，由后端生成不可变候选快照。之后新增的上传、审核和点赞不影响当前轮次。前端使用快照完成加权随机和动画，结果提交后端保存。

照片云动画只负责表现，中奖结果应在动画开始前确定，避免动画性能影响结果。

## 8. 图片显示规格

OSS 只保存原图。应用统一封装 URL 生成器，提供以下预设：

```text
thumbnail：照片墙缩略图，例如 400 × 400 裁切
gallery：移动端预览，例如长边 1200px
review：审核预览，例如长边 1600px
draw：抽奖大图，例如长边 1920px
```

具体 OSS 参数集中在一个服务或工具函数中维护，不允许散落在页面组件里。

## 9. 非目标

本项目不计划实现：

- 短信验证码
- 多角色和复杂权限系统
- Redis 缓存
- 人脸识别或视觉重复照片识别
- 长期内容运营
- 独立缩略图生成服务
- 高并发分布式架构
